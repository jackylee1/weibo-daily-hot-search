# PDD 商品图片采集与整理流程（2026-10-24）

## 目的与边界

本文记录 Batch 16 拼多多商品图片包的可核验事实，并给后续任务一套可复用、尊重站点访问控制的采集与整理流程。

“避免 IP 被封”在本文中指降低正常访问带来的误伤并遵守平台限制，不包括绕过访问控制。不要使用代理池/IP 轮换、伪造设备指纹、绕过验证码、破解签名、伪造登录态、隐藏自动化或针对封禁继续重试。遇到访问拒绝、验证码、限流或登录墙时应停止该商品的自动请求，转为用户授权的正常浏览器操作、平台提供的导出/API，或取得平台/权利人的授权。

## 本批次可以核验的事实

- 用户给出的清单包含 41 个商品链接，分四轮整理。
- 下载清单 download_manifest.csv 记录 325 个原始图片文件及对应商品、序号、文件名、来源 CDN URL、MIME 类型和下载状态。
- URL 主机包括 img.pddpic.com、img-4.pddpic.com；若干 URL 带有 imageMogr2/quality/90/thumbnail/1300x9999> 图像处理参数。
- 原图按商品和资源序号保留，没有去重。组织副本按主图/详情图分开，但该分类是根据页面资源顺序推断，并非逐一人工确认。
- 配套英文图片为原图的 OCR/翻译处理版本，不等同于人工校对完成或可直接上架的内容。
- SKU/变种选择图没有完成核验或采集。不得把详情图误报为变种图。
- 生成的英文 AI 重绘图是概念样稿；清单状态不是“可上架”。重绘不能证明产品参数、结构、兼容性或供应商授权。
- 本地包没有保存原始浏览器资源面板/网络日志、完整下载脚本或逐图 HTTP 响应日志。因此不能从现有证据断言当时每一张图是通过哪种浏览器提取手段取得，也不应补写一个虚构的“已执行脚本流程”。

## 后续复用的合规流程

### 1. 建立输入清单

对每个商品保存用户提供的商品 URL、商品 ID、轮次、商品名和访问日期。先用已授权的正常浏览器会话访问页面，检查是否需要登录、是否可见、是否触发验证。保持人工可见、用户可控；只处理用户指定的商品和公开/已授权可访问的素材。

### 2. 分别识别图片区域

逐个商品检查并分别记录：

1. 手机端商品主图轮播：逐张切换到位，记录每张的原始顺序和 CDN 地址；保留相似图、不同件数图和轻微差异图，不擅自去重。
2. 商品详情长图：按页面顺序记录所有图片，不能只保存首屏。
3. SKU/变种图：打开变种选择区，逐一选中可见变种并记录对应图片与选项文字。未实际选择/看见的变种标为“未核实”，不要推测。
4. 页面加载失败、验证码或需要额外授权的资源：记录状态和截图/时间，不尝试绕过。

页面当前状态可能因登录、地区、商品下架或动态加载而不同；商品链接列表本身不代表每个区域都已被读取。

### 3. 获取图片文件

优先使用平台官方导出/API或正常浏览器提供的保存功能。对页面本身合法显示、且访问权限允许的 CDN 图片，记录页面展示顺序和直接来源 URL，再按站点条款允许的方式保存。只访问页面实际引用的图片 URL；不要枚举 CDN 路径、扫描其他商品、破解 URL 签名或仿造站点私有接口。

若站点要求低频访问，按其规则执行；未明确频率时，以串行、低速、少量访问为准，不进行并发洪泛。保存每个请求的时间、状态码、Content-Type、文件大小；若平台条款不允许自动化下载，就改用人工保存或申请授权。

### 4. 面对限流、验证码和 IP 拒绝

- 收到 HTTP 403/429、验证码、访问拒绝、登录墙或平台明确提示时，立即停止该站点/会话的自动获取。
- 不换代理/IP、不清洗指纹、不绕验证、不轮询账号继续请求。
- 对 429 仅在平台明确允许重试且提供 Retry-After 时，遵照该等待时间；否则停止并记录。
- 记录商品 URL、时间、页面实际提示、状态码（如可见）和已成功文件数。
- 让用户在其正常登录的浏览器中完成必要的人机验证，或改用平台官方批量导出/开放接口/授权数据源。不要索取或记录密码、Cookie、令牌等登录凭据。
- 恢复访问前先确认平台规则或获得授权；不要把降低请求频率描述成可绕过封禁的手段。

### 5. 目录、命名和清单

建议每个商品独立目录，并按以下类别分开存放：source/main_gallery、source/detail、source/variant_selection；英文直译版对应使用 english_literal 子目录；AI 重绘版使用 english_redrawn 子目录。

原始文件名包含稳定序号和原始文件标识，例如 01_原资源ID.jpg。不要覆盖原图，不去重；同一图片的重复引用也保留并在清单中标记。英文输出使用可读的中英文文件名，AI 样图名另含 AI_Redraw 和 NotForListing。

至少记录这些字段：轮次、商品序号、商品 ID、商品名称、来源页面 URL、资源区域（主图/详情/变种）、页面顺序、原始 CDN URL、落盘相对路径、MIME 类型、字节数、HTTP 状态、采集时间、校验和（SHA-256）、翻译/重绘状态、审核备注。

### 6. 文件完整性与人工核对

- 比对清单行数、落盘文件数和每商品资源数量；检查 0 字节/错误 MIME/无法打开的文件。
- 为每个源图生成 SHA-256；重复文件不删除，只记录相同哈希。
- 建立逐商品缩略图索引，人工确认主图、详情图和变种图分区是否正确。
- 重新打开预览页，检查全部本地图片链接和对应来源链接。
- 对平台实际显示数量与采集数量不一致的商品，标记差异；不要用“全部”或“完整”描述未经核验的区域。

### 7. 英文版与 AI 重绘版的区分

- 英文直译版应保留原布局和产品图，只替换可辨识中文；低置信 OCR 标出待人工复核，不猜字。
- AI 重绘版另存新文件，不覆盖原图或直译图。仅以来源图中能确认的外观为依据。
- 删除无法核实的品牌、适配型号、认证、过滤精度、去除率、杀菌、寿命、数量、尺寸、材质等级等文字；生成图中不应添加卖点或安全/性能承诺。
- 生成物须由供应商核对实物结构、参数、配件和数量。没有供应商确认、产品授权或权利核查时，保留“概念样稿/未批准上架”状态。
- 来源商品图、商标和设计可能受版权/商标/外观设计保护。下载、翻译或用 AI 重绘并不会自动授予商业使用权；刊登前核查授权和平台规则。

## 本地批次的复核入口

- download_manifest.csv：325 个图片资源及 CDN 来源 URL。
- organized_image_manifest.csv：按主图/详情等分类的组织清单；分类为推断。
- variant_image_status.csv：41 个商品的变种图片核验状态。
- english_image_manifest.csv：原图到英文直译文件的对应关系。
- english_redrawn_manifest.csv：AI 样稿与来源图对应表。
- source_links_status.csv：用户提供商品链接状态。
- organized/index.html：本地图片对照预览。
- README.md 与 organized/ENGLISH_REDRAWN_STATUS.txt：批次计数和完成状态。

## 给后续 AI 任务的简短规则

先读本说明和清单；逐商品串行处理；保持用户提供的顺序，不去重；原图、直译图、AI 重绘图分开存储并记录来源。不要声称未核验的变种/详情区域已完整。遇到验证码、限流、403/429 或权限限制立即停止自动访问，记录真实状态并转向官方导出/授权来源；不要尝试绕过 IP 封锁或反爬措施。
