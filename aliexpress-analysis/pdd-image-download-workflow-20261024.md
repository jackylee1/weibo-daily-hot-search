# PDD 商品图片提取与本地下载：方法、边界与脚本审查

- 整理日期：2026-10-24
- 用途：供后续 Codex 任务参考从用户可访问的商品页或已导出商品 JSON 中整理图片、下载到本地的流程。
- 状态：对用户粘贴的 Node.js 脚本做静态审查；本次未运行脚本，也未触发下载。
- 范围：仅处理正常可访问页面已经提供的公开图片 URL。

## 结论

Node.js 下载器只能保存已经取得的图片 URL。空的 `thumbUrl` 无法推导出SKU图，普通商品页数据也不能证明已包含APP专属轮播或SKU图库。

FY2401 案例：页面核对到 1 张主图、10 张详情图；3 条SKU记录缺少可用的选项名称和图片URL。因此按脚本现有输入，下载任务最多为11张图片，不包括SKU图。图片计数相符不证明图片身份、顺序或APP图库完整。

## 推荐流程

1. 在用户授权的浏览器中正常打开商品页，等待页面主体及懒加载图片显示；记录入口类型和检查日期。
2. 仅导出必要字段：商品ID、来源标题、主图URL数组、详情图URL数组、SKU规格字段及SKU缩略图URL。不要上传完整 `window.rawData`、Cookie、登录令牌、买家或账户数据。
3. 按字段提取并保留原始顺序：
   - 主图候选：`goods.viewImageData` 或 `goods.topGallery`
   - 详情图候选：`goods.detailGallery` 和 `oakData.goods.decoration[].contents[].imgUrl`
   - SKU候选：`goods.skus[].thumbUrl` 及规格字段
   - 字段缺失时标“未提供”，不猜测，也不把示例占位值当真实数据。
4. 按商品分目录保存：`source/main_gallery/`、`source/detail/`、`source/variant_selection/`。使用有上限的小规模并发（例如4–6项），避免数百个请求同时发出。
5. 保留原始顺序、重复项、完整源URL和下载字节。Manifest记录商品ID、图片角色、序号、源URL、本地路径、HTTP状态、Content-Type、字节数、SHA-256和错误信息。用户未要求去重时不去重，不覆盖原始文件。
6. 将本地数量与同一时点页面可见的主图/详情图数比较，SKU图单独核验。数量相等不证明内容和顺序一致；页面显示更多图片时记录差额并标为未完成。

## 对粘贴脚本的审查

### 能做的事

- 解析一种特定的导出JSON结构：`store.initDataObj.goods` 和 `store.oakData.goods`。
- 从已知字段整理主图、详情图和非空 SKU `thumbUrl`。
- 建立本地商品文件夹，并通过 HTTPS 保存已知图片URL。

### 不能据此声称的事

- 不能取得JSON未包含的图片；空 `thumbUrl` 就没有可供该脚本下载的SKU图。
- 不能证明已收齐APP轮播、所有购买变种图或整页素材。
- 不能把详情图片归类成SKU图，也不能把脚本默认值当作真实价格、库存或规格。

### 运行前应修复

- 移除硬编码默认商品字段，尤其默认价格、库存数量和“默认规格”；缺失值写为 `unknown / not provided`。
- 脚本用 `Set` 合并详情URL，会去重，违反保留所有原图和顺序的要求。
- 脚本用 `split('?')[0]` 删除查询参数。部分URL可能带签名或图片变体参数；默认保留完整URL和源记录。
- 所有文件强制用 `.jpg` 后缀，可能把PNG/WebP内容错标。应根据实际响应类型保存扩展名。
- 对全部任务直接使用 `Promise.allSettled`，没有并发上限；应加有界队列。
- 重定向递归缺少跳转次数、超时、文件大小上限和可靠清理；逐项处理状态码、流错误和中断。
- 当前只打印成功数，不输出逐项失败原因；Manifest必须记录失败URL及原因。
- 校验商品ID和文件名以防路径越界；下载源限制为预期图片CDN主机。
- 校验响应类型和文件内容，避免把HTML错误页保存为图片。

## FY2401 核对实例

- 页面：`https://mobile.yangkeduo.com/goods.html?goods_id=673950709510`
- 核对日期：2026-10-24。
- 页面/本地核对：主图1张、详情图10张，总计11张。
- SKU：3条记录，但规格名称和 `thumbUrl` 未能核实；确认到的SKU图片为0张。
- 型号信息存在冲突：商品清单标题和图片OCR识别到的型号列表不一致。正式文案应等供应商或实物确认，不由解析器自动合并。
- 结论：可保存11个已知图片URL；此法不能补出缺失的APP专属SKU图。

## 访问限制与数据安全

- 仅使用正常页面访问、用户提供的页面状态或页面公开提供的图片URL。
- 不使用代理/IP轮换、验证码规避、指纹伪装、Cookie提取或未授权私有接口重放。
- 遇到限流、403、验证码或拒绝访问时，停止自动重试并记录状态；改用用户导出的图片包、获授权供应商素材或稍后正常访问。
- 页面可见不代表有商业使用权；上架前确认图片授权，并审核英文翻译图、重绘概念图与商品实物的一致性和文案声明。

## 验收清单

- 解析失败即停止；不以时间戳伪造商品ID。
- 每个图片条目保留角色、顺序和原始URL；重复URL仍分别保留条目。
- 并发数、超时、最大文件大小和最大跳转次数都有上限。
- 文件能解码为图片，扩展名符合实际格式。
- Manifest逐项写明成功或失败及原因。
- 详情图与SKU图分开计数；未获取的SKU图明确标为未取得。
- 记录页面计数、当地归档计数和日期；不以数量相同推定内容完整。
